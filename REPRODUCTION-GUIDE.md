# Reproduction Prompt: AI in Research — Case Library

## What to Build

A responsive, scroll-driven case library showing seven cases on how AI infrastructures support (or fail) underrecognised disciplines, entities and non-traditional researchers in AI-enabled research. The library has two views per case — a **story** (scrollytelling with charts) and a **dossier** (layered skim/read/deep interface) — plus a landing page with case cards and cross-case synthesis.

Everything is built from **plain Markdown files**, parsed by a Python script into structured JSON, rendered in vanilla JavaScript/SVG with no build step or framework.

## Step 1 — Write Case Studies in Markdown

Each case file follows the exact structure defined by the appraisal checklist template. Here is the required format:

### Required Headings (in order)

```markdown
# <Case Title>

**Label: <Positive | Contested | Ambiguous | Negative>.</strong> <One-sentence verdict.>

## Sources
- <Source 1> — <Description> [optional tags: **[VERIFY]** or **[not opened]**]
- <Source 2>

## Background
<Paragraph(s) describing the case in narrative form. Use **bold** for emphasis, \`code\` for technical terms, and https://urls for links.>

## Who did what
| Role | Contribution |
|---|---|
| **Humans** | <description> |
| **AI** | <description> |
| **Checkpoint** | <what verified the outcome> |

## Progress made
| Claim | Status | Evidence |
|---|---|---|
| <claim text> | Verified / Reported / Claimed / Plausible / Possible / Risk / Contested / Disputed / Not shown / Open question | <evidence description> |

## Harm and risk
| Risk | Who is affected | Status |
|---|---|---|
| <risk text> | <who> | <same status keys as above> |

## Deep dive 1.1 — <Topic>
**The question:** <short question the deep dive answers>

<narrative paragraphs with **Reading.** and **Push back.** callouts:>
> **Reading.** <supporting argument>
> **Push back.** <counter-argument>

<optional tables or numbered lists here>

<optional Debate A: / Debate B: sections with Position AB labels and bullet points>

**For discussion:** <discussion prompt for educators>

## Deep dive 1.2 — <Topic>
[same structure]

## Deep dive 1.3 — <Topic>
[same structure]

## Deep dive 1.4 — <Topic>
[same structure]

## What a scientist needs to know
- <bullet point>
- <bullet point>
- <bullet point>

## Decision point
<short scenario paragraph that forces a choice>

## Activity
### <Activity Title>
<activity description with numbered steps>

## Recommendations
| Audience | Action |
|---|---|
| <audience name> | <actionable recommendation> |
| <audience name> | <actionable recommendation> |

<optional NOTE: <important caveat>>
<optional **Takeaway:** <one-sentence key insight>>
```

### Status Keys (determine color coding throughout)

| Status Key | Color | Meaning |
|---|---|---|
| `Verified` / `Documented` | #2a9d5c (green) | Confirmed by authoritative source |
| `Reported` | #3a7bd5 (blue) | Reported in sources, not independently verified |
| `Claimed` | #e0a100 (amber) | Stated by the case actors themselves |
| `Plausible` / `Possible` / `Potential` / `Risk` | #8e6bd1 (purple) | Inferred, speculative, or uncertain |
| `Contested` | #e8731a (orange) | Disputed among experts |
| `Disputed` | #d1342f (red) | Actively contested |
| `Not shown` / `Open question` | #8a8a8a (grey) | No evidence available |

### Required Deep Dives (every case must have all four)

1. **Deep dive 1.1 — Was AI necessary?** — Compare to non-AI alternatives. Must include: The question, supporting Reading, counter-argument Push back, discussion prompt.
2. **Deep dive 1.2 — Disciplinary advance** — Measured changes rather than claimed ones. Use numbered lists and tables where possible.
3. **Deep dive 1.3 — Ethical considerations** — Map to appraisal checklist items (esp. items 7–16). Use expandable `<details>` sections with Debate A / Debate B framing.
4. **Deep dive 1.4 — Alternative views** — Present at least two positions (Position A / Position B) with bullet-point arguments, plus a slider-style third option and discussion prompt.

## Step 3 — Run build.py to Generate Data

```bash
cd designs/
python3 build.py
```

`build.py`:
- Reads all case `.md` files from the repo root
- Parses headings (## Section → h3), pipe tables, bullet/numbered lists, blockquotes, paragraphs, inline bold/italic/code/links
- Outputs `data/cases.js` with `window.CASES = { slug: parsedCase, ... }` and `window.SYNTHESIS = parsedSynthesis`
- Also reads `cross-case-synthesis.md` for the cross-case overview

The generated JSON structure per case:
```javascript
{
  slug: "alphafold",
  file: "alphafold.md",
  title: "AlphaFold",
  label: { tag: "Ambiguous", html: "Open release is a genuine and uncommon good..." },
  callouts: [{ paras: ["...", "..."] }],  // from > blockquotes before first heading
  sections: [
    { title: "Sources", blocks: [...] },
    { title: "Background", blocks: [...] },
    { title: "Who did what", blocks: [table, ...] },
    { title: "Progress made", blocks: [table, ...] },
    { title: "Harm and risk", blocks: [table, ...] },
    { title: "Deep dive 1.1 — Was AI necessary?", blocks: [...] },
    // ... one section per ## heading
  ]
}
```

## Step 4 — Add Per-Case Visual Extras (optional but recommended)

File: `designs/data/extras.js`

For each case slug, add a visual customization object:

```javascript
window.EXTRAS = {
  "case-slug": {
    kicker: "<category label>",           // e.g. "Mathematics · Agentic AI"
    hook: "<one-sentence summary>",        // shown on cards and hero
    stats: [                               // key numbers for hero stats row
      { n: "10k", l: "AI agents running at once" },
      { n: "88 h", l: "to a solution" }
    ],
    viz: "timeline | flow | bars | dumb",  // preferred chart type (default: timeline)
    
    // For timeline charts:
    timelineBand: "<band label>",           // shown at bottom of timeline
    timeline: [                            // events [{date, t (day offset), label, detail, key}]
      { date: "1 Sep", t: 1, label: "Effort begins", detail: "...", key: false },
      { date: "8 Sep", t: 8, label: "Announced", detail: "...", key: true }  // key event
    ],
    
    // For scrollytelling steps (overrides background paragraphs):
    steps: [                               // [{ v (step index), html }]
      { v: 0, html: "On <strong>1 September</strong>, ..." },
      { v: 1, html: "About <strong>10,000 agents</strong>..." }
    ],
    
    // For flow charts (process pipeline):
    flow: {                                // [{ stages, done, gates }]
      stages: ["Step 1", "Step 2", "Step 3"],
      done: 2,                              // how many steps are complete
      gates: [
        { after: 1, label: "Peer review", ok: false }
      ]
    },
    
    // Glossary terms displayed inline:
    glossary: {
      "<Term>": "<definition>",
      "...": "..."
    }
  }
};
```

If no extras entry exists for a case, it still renders with generic fallbacks (default chart type, background paragraphs as scroll steps).

## Step 5 — Implement the Three HTML Views

### 5a. Landing Page (`index.html`)

**Layout:**
- Hero section with eyebrow label, H1 "AI in Research", italic question subtitle, intro paragraph
- Two purpose cards: "Build evaluations" and "Build sensitivity"
- "How to explore" callout box explaining story vs dossier modes
- Case cards section organized into three groups (defined in code):
  - Group 1: "AI claims and tools in science" — alphafold, navier-stokes, virtual-lab, long-tail-research
  - Group 2: "Problem classes" — undue-influence, morally-inadmissible
  - Group 3: "Misuse of AI against research" — word-weaponization
- Cross-case overview section (from `window.SYNTHESIS`): five ethical patterns + was-AI-necessary table + side-by-side table
- Footer with verification disclaimer

**Design tokens:**
```css
:root {
  --paper: #fbf5ea; --ink: #1d1a16; --muted: #c9bfae;
  --accent: #e4572e; --accent2: #2a7f86; --tint: #f3eadb;
  --serif: "Iowan Old Style", "Palatino Linotype", Palatino, Georgia, serif;
  --sans: "Avenir Next", "Segoe UI", system-ui, sans-serif;
}
```

**Card rendering (per case):**
- Kicker label → Case title with link to `story.html?case=<slug>`
- Label pill colored by tag (Positive=#2a9d5c, Contested=#e8731a, Ambiguous=#8e6bd1, Negative=#d1342f)
- Hook text from extras
- Facts grid: Main risk, Lesson, Was AI necessary? (from cross-case synthesis table)
- Alt link to dossier view

**Cross-case overview:** Render sections from `window.SYNTHESIS` using `window.renderBlocks()`. Links to case markdown files should be rewritten to point to `story.html?case=<slug>`. Extract the "Side by side" table for rendering; extract "Was AI necessary?" data as a facts grid on each card.

**Responsive:** Cards grid `auto-fill, minmax(300px, 1fr)`, clamp typography.

### 5b. Story View (`story.html`)

**Sections (rendered via JavaScript):**
1. **Hero** — Kicker label, case title, hook subtitle, verdict stamp, "Read as dossier" link, scroll cue
2. **Key numbers row** — Stats from `extras.stats` (animated entrance)
3. **Chapter 1: Background** — Scrollable left text with sticky right chart (`vizTimeline`, `vizFlow`, or `vizBars`)
   - Steps driven by `extras.steps` (fallback to background paragraphs)
   - Chart advances as steps become visible (IntersectionObserver)
4. **Chapter 2: Who did what** — Grid of role cards (Humans=teal, AI=accent, Checkpoint=ink)
5. **Chapter 3: Progress made** — Expandable claims list with status bars and color-coded pills
6. **Chapter 4: Harm and risk** — Risk cards with accent-colored left borders and status dots
7. **Chapter 5: Deep dives (x4)** — Each with its own chart area:
   - DD1 "Was AI necessary?" → `versus` layout (Reading vs Push back), discussion prompt
   - DD2 "Disciplinary advance" → Numbered list or table in `.stack` layout
   - DD3 "Ethical considerations" → Ethics details with Debate A/B, slider for third option
   - DD4 "Alternative views" → Two-column debate layout with Position cards + slider
8. **Chapter 6: What a scientist needs to know** — Checklist with checkboxes
9. **Chapter 7: Decision point** — Scenario paragraph + textarea input for user response
10. **Activity section** — Boxed activity description with numbered steps
11. **Recommendations** — Tabbed interface (Researchers | Tool builders | Funders) with audience/action pairs
12. **Finale** — Dark background, one-sentence takeaway in large serif type
13. **Back matter** — Sources list, NOTE if present

**Scroll features:**
- Reading progress bar at top
- Chapter navigation dots (right side) with hover tooltips
- Top nav switching between story/dossier views
- Sticky figure panels that scroll as background steps advance
- Fade-in/slide-up on intersection for stat rows, risk cards, claim items, numbered list items

**Responsive:** Scrolly grid collapses to single column on mobile; figure moves above text with sticky top. Chapter nav hidden on small screens.

### 5c. Dossier View (`dossier.html`)

**Three-column layout:**
- **Left: Table of contents** (sticky) — scroll-linked section anchors + character count info
- **Center: Main content** — Case title masthead, verdict bar, skim/Read/deep toggle, all case sections
- **Right: Glossary & tools** (sticky) — collapsible glossary terms

**Depth modes:**
- **Skim**: Summary blocks only — hook, key numbers, status pills, first sentence of each section
- **Read**: Full paragraph text + tables (default mode)
- **Deep**: Expands debate sections, detailed visualizations, full sources

**Key components:**
- Depth toggle pill button group
- Section headers with numbered badges in accent color
- Status chip pills for claims and risks using `window.STATUS` map
- Risk table rendered as bordered table
- Claim expanders (click row → reveal evidence)
- "Who did what" grid (120px role column + description)
- Recommendation tabs (Researchers / Tool builders / Funders)

**Design tokens:** White paper background, Inter/Helvetica sans-serif feel with Charter/Georgia serif for body. Accent color #2f54eb (blue).

## Step 6 — Shared Libraries

### `shared/base.css`
- CSS custom properties for all colors, typography, spacing
- Utility classes: `.wrap`, `.eyebrow`, `.pill`, `.tablewrap`
- Responsive breakpoints at 820px and 1150px
- SVG chart styles via CSS variables on container (`.viz { --ink, --accent, --muted, ... }`)

### `shared/model.js`
Exports these global functions:
- `buildModel(slug)` → case model object with all parsed fields
- `renderBlocks(blocks)` → HTML string from block array
- `stripTags(html)` → plain text extraction
- `firstSentence(html)` → first sentence only
- `leadSplit(html)` → split "Lead. rest" into {lead, rest}
- `caseSlug()` → extract `?case=` param or fallback
- `STATUS` map: status key → {label, color}

### `shared/viz.js`
SVG visualization functions (all accept `(el, data, activeIndex, options)`:
- `vizTimeline(el, events[], active, {width, height, band})` — vertical timeline with dots/lines/dates
- `vizFlow(el, {stages[], done, gates[{after, label, ok}]}, active, {vertical})` — pipeline process chart
- `vizBars(el, {labels[], values[], colorFn()}, active)` — bar chart for comparisons

## Design Notes for Reproduction

- **No framework or build step** — pure HTML/CSS/JS with vanilla fetch-free data loading
- **All CSS custom properties** can be swapped to restyle entirely (dossier.html shows a different palette than story/index)
- **Charts are inline SVG** generated by JavaScript — no chart library dependency
- **Scroll-driven animation** via IntersectionObserver (steps highlight as they enter viewport, stat rows fade in)
- **URL-based routing** via `?case=slug` query param — no router needed
- **The parser is deliberately small** (~150 lines) — it handles only the subset of Markdown actually used: headings (# through ###), pipe tables, unordered/ordered lists, blockquotes (>), paragraphs, inline bold/italic/code/links/URLs
- **`extras.js` is optional per-case** — cases without extras entries render with sensible defaults (default chart type = timeline, background paragraphs = scroll steps)
- **Two design languages coexist**: warm paper tones (#fbf5ea background, Palatino serif) for index/story vs clean white (#ffffff background, Inter/Charter serif) for dossier
